## 一句话结论

这是一个有鲜明作者性、题材稀缺、核心想法成立的政治模拟游戏。它已经“有趣”，但目前的乐趣更多来自文本人格和系统想象，而不是来自清晰、稳定、可预期的策略操作反馈。它像一部会运转的明末政治机器，但还需要把“我做了什么 -> 世界怎么变 -> 下一步我为何要这么做”这条玩家兴奋链路做得更锋利。

## 好不好玩

好玩，但不是轻松好玩。最强的部分是“人治”这个核心幻想：我不是在拖动抽象资源条，而是在通过王承恩传召毕自严，让一个具体的人带着官职、立场、顾虑来回应我。毕自严没有机械执行“拟旨”，而是反问关宁/京营怎么分银、陕西五日内能否真正放赈、五万盐课商税是经费还是追缴目标。这很像一个真官员，历史味很足。

问题是这份聪明会反咬节奏。我作为玩家明明在找“帮我拟旨”的按钮，结果大臣把我带回三段执行论证。模拟上合理，游戏性上挫败：我没有得到一个可操作草案，也没有一个“采纳他的追问继续拟旨”的快捷桥。最后我用手动旨意继续闭环，这说明系统深，但行动闭环还不够顺。

当前乐趣评分：7/10。  
如果把行动闭环、反馈高亮和信息层级补上，有潜力到 8.5/10。

## 流程健康

1. 菜单：健康。入口明确，题材气质强。
2. 首次引导：中等。概念讲清楚了，但字多，手机首屏压力偏大。
3. 首页：健康。今日要务、随侍、复命、朝报把“现在该干什么”摆出来了。
4. 召对入口：健康。必须通过随侍传召，这个设计很有味道。
5. 传召名单：可用但弱。人物很多，缺少搜索、筛选、推荐理由。
6. 大臣聊天：最有魅力，也最危险。人格感强，但回复长、等待久，Markdown 标记裸露，且“拟旨”意图未稳定转成草案。
7. 诏旨页：功能成立。草案、拟诏、颁布、在办、复命都在一个页内完成。
8. 拟诏编辑：仪式感强，但手机编辑大段诏书很累。
9. 推时日/复命：系统成立。指令会到期，会有复命，会改变局势。
10. 事件插入：有戏，但会抢反馈。复命时先弹出宿敌互讦裁断，遮住了我刚刚等待的旨意结果。
11. 天下反馈：方向正确。中兴指数和地图很像策略游戏，但没有高亮“刚才那道旨意改变了什么”。
12. 桌面：比之前合理。760px 居中后不再像窄手机被拉到桌面中间，但仍是移动壳体验，不是完整桌面策略 UI。

## 主要问题

### P0 / P1：拟旨意图没有稳定落成可执行草案

证据：`07-minister-chat-response.png`。  
我明确要求毕自严“替朕拟一道可直接颁布的旨意”，他给了合理反问，但没有生成 `proposed_directive`。这不是模型质量差，恰恰是角色太认真。但从游戏角度，玩家的行动链断了。

建议：
- 当玩家使用“拟旨”建议或输入含“拟旨/可颁布/旨意”时，回复末尾必须给一个可核定草案。
- 如果大臣认为条件不明，可以生成“保守版草案 + 需陛下裁定的三项可选参数”。
- 在聊天回复底部加操作按钮：`按毕自严建议拟旨`、`补问分银方案`、`强令照办`。

### P1：复命反馈被同日裁断事件抢焦点

证据：`11-edicts-settled.png`。  
我推时日等复命，结果先看到“宿敌互讦”裁断弹窗。这事件本身不错，但它遮住了刚才最期待的复命。

建议：
- 同日多事件按玩家期待排序：先展示“玩家主动等待的旨意复命”，再展示朝堂突发。
- 增加“今日回响队列”：复命、奏疏、裁断按卡片排队，玩家逐条处理。
- 弹窗上标明“还有 1 道诏书复命待阅”，避免玩家误以为主线反馈消失。

### P1：结果缺少即时数值摘要

证据：`11b-edicts-settled-clear.png`、`12b-realm-after-clear.png`。  
复命卡有文本，但没有直接显示：国库 -45、内库 -5、辽东索饷 +20、陕西流寇 +15、户部亏空 -5、欠饷减少 45。玩家要去脑补或跨面板找。

建议：
- 每条复命卡追加“结果摘要”区：银两、局势条、地区动乱、军队欠饷。
- 首页“诏书复命”卡显示关键变化，而不是只显示奏报正文。
- 天下页高亮最近一次变动的省份/军队/局势项，持续一回合。

### P1：手机长文本阅读与编辑压力过大

证据：`07-minister-chat-response.png`、`09-decree-editor.png`。  
大臣回复很长，诏书 textarea 也很长。字体有古雅气质，但手机上一屏吸收负担重。

建议：
- 大臣回复拆成“结论 / 风险 / 可下旨草案”三段折叠。
- 默认显示摘要，展开看全文。
- 拟诏编辑提供结构化字段：款项、对象、期限、主办、严禁事项；诏书全文作为预览。

### P2：传召名单缺少决策辅助

证据：`05-summon-sheet.png`。  
人物多，有头像和职位，但玩家不知道此刻该找谁。

建议：
- 加搜索。
- 加筛选：财政、边防、党争、内廷、地方。
- 在今日要务里点“户部亏空”时，传召页默认推荐毕自严、户部相关官员，并说明推荐原因。

### P2：Markdown 标记裸露

证据：`07-minister-chat-response.png`。  
回复里出现 `**其三**` 这类标记。会破坏古典文本质感。

建议：
- 聊天气泡渲染安全 Markdown，或在模型输出后清理 `**`。
- 对列表结构用原生段落样式，不让模型控制格式。

### P2：桌面端仍是放大版移动体验

证据：`13-desktop-current.png`。  
当前 760px 居中已经明显好于窄栏，但桌面大屏没有利用横向空间。

建议：
- 桌面改为三栏：左侧御前/召对，中间当前任务/奏疏/诏旨，右侧天下反馈/复命日志。
- 移动保留底部 tab；桌面用固定侧栏或顶部宫廷导航。
- 桌面把“地图 + 局势条 + 最近变动”并排，减少深滚动。

## 最值得保留的设计

- “随侍太监是门”这个设计非常好，立刻让游戏区别于普通策略面板。
- 大臣会反问、会保守、会考虑执行链，说明角色不是按钮。
- 诏旨从草案到颁布再到复命，这条链已经成立。
- 中兴指数和地图是长期目标感的雏形。
- 顶部三道国势（君威、任事、精力）比常规资源栏更贴合主题。

## 优先改进路线

1. 先修行动闭环：拟旨意图必须稳定产出草案，或给一键生成保守草案。
2. 再修反馈闭环：复命卡必须展示数值摘要和“影响了哪里”。
3. 然后修事件队列：玩家等待的结果优先展示，突发事件排队。
4. 再做文本分层：长回复摘要化，全文可展开。
5. 最后做桌面布局：移动壳保留，桌面做三栏工作台。

## 最终判断

这个游戏的方向是对的，而且已经有“只有它能给”的体验：大明不是一张表，而是一群人和一套会磨损、会拖延、会反问你的官僚机器。它现在不好玩的地方，不是系统不够，而是系统太聪明、UI 太诚实，把复杂度原样交给玩家。

真正的提升方向不是再加更多机制，而是把现有机制变成更清楚的玩家回路：

说服某人 -> 生成草案 -> 颁布 -> 等待 -> 复命 -> 看见数值和地图变化 -> 产生下一步冲动。

这条链一旦被打磨顺，游戏会很有抓力。
