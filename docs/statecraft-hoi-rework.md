# 国家机器重构：参考钢铁之心的经济与官僚组织

## 目标

当前问题不是“没有经济”和“没有官僚”，而是它们散成了很多局部系统：财政账、建筑、军饷、组织图、官职、承办评估、国策约束各说各话。玩家无法像在《钢铁之心》里那样一眼看出：

- 我现在有什么库存。
- 每月自然流入/流出多少。
- 哪个产能在限制我。
- 哪个部门缺人导致命令慢、贵、变形。
- 下一步应该补财政、补官、修工坊、拨军饷，还是换路线。

本重构新增 `StatecraftCenter`，把经济和官僚组织统一为“国家机器”面板。它不新增第二套经济账，也不新增第二套官僚状态表；只聚合 `FiscalCenter` 与 `organization_diagnostics()`。

## 钢铁之心式映射

| HoI 概念 | 本游戏映射 | 说明 |
|----------|------------|------|
| 顶栏资源 | 国库、内库、欠饷、朝廷执行力 | 先看库存和国家机器总体状态 |
| 民用工厂 | 营造/工部/地方贯彻能力 | 决定建筑、仓廪、炮厂、水利、维护压力 |
| 军工厂 | 军政后勤 + 军器建筑 | 决定军饷、训练、调防、火器和边镇执行 |
| 政治点数 | 诏旨注意力 + 官僚程序能力 | 决定批红、廷议、任命、合法性成本 |
| 国家精神 | 国策/遗产 modifiers | 决定财政、派系、执行阻力和长期路线 |
| 生产线 | 在办旨意 / 建筑 / 军务 / 财政改革 | 每条线消耗钱、部门产能、承办人和时间 |
| 后勤缺口 | 欠饷、建筑失修、地方动乱 | 不是单纯余额数字，而是执行折损来源 |
| 警报灯 | `bottlenecks` | 告诉玩家先补哪里，否则命令会慢或变形 |

不能照搬的部分：

- 晚明不是现代工业国，不能把所有东西都压成“工厂数”。
- 官僚不是无人格机器，部门产能必须继续受人物、派系、空缺、兼差和召对背书影响。
- 经济不能只看总 GDP，必须保留国库/内库、税源到账、欠饷和一次性流水。

## 新玩家模型

国家机器面板按四层读：

1. **库存**：国库、内库、欠饷、朝廷执行力。
2. **月流**：国库税源、国库支出、内库收支、营造资产净贡献。
3. **产能**：财政署理、军政后勤、营造军工、地方贯彻、铨选任官、票拟程序、厂卫监察、内廷传旨。
4. **瓶颈**：现金缺口、欠饷、部门断裂、建筑失修、机构执行风险。

玩家不需要先读所有奏报。只要看这四层，就能知道国家机器为什么跑不动。

## 后端实现

新增：

- `ming_sim/statecraft_center.py`
- `GET /api/statecraft_center`
- `directive_statecraft_preflight(text, statecraft)`：把单道旨意映射到相关产能和瓶颈。

返回字段：

- `topbar`：国库、内库、国库月净、朝廷执行力、欠饷。
- `economy_lanes`：国库税源、国库支出、内库收支、营造资产。
- `capacity_rows`：各官僚产能领域的分数、状态、影响、薄弱机构。
- `building_capacity_rows`：按建筑类别聚合数量、状态、产出、维护和风险。
- `bureaucracy_rows`：机构执行力、覆盖率、在任质量、空缺、风险。
- `bottlenecks`：玩家应优先处理的国家机器瓶颈。
- `source_links`：指向财政、官制、国策源接口。

`GET /api/directives/lifecycle` 也会为每道旨意附带 `statecraft_preflight`：

- `domains`：旨意涉及的财政、军政、营造、地方、程序等领域。
- `score/status/tone`：相关国家机器产能综合预审。
- `capacity_rows`：直接影响此旨的部门产能。
- `bottlenecks`：会让此旨变慢、变贵或走样的瓶颈。

数据纪律：

- 经济账继续以 `FiscalCenter` 为唯一解释层。
- 财政预算继续以 `compute_budget_lines()` 为唯一预算入口。
- 余额变化继续以 `economy_ledger` 为唯一流水入口。
- 官僚产能继续以 `organization_diagnostics()` 为唯一组织诊断入口。
- `StatecraftCenter` 只聚合，不改账、不改官、不结算。

## 官僚组织重排

官僚组织不再只是“谁坐在哪个衙门”的图。每个机构必须产出可审计能力：

| 能力 | 主要来源 | 影响 |
|------|----------|------|
| 财政署理 | 户部、地方、监察 | 税源清查、军饷调度、财政改革 |
| 军政后勤 | 兵部、边镇、内廷监军 | 调兵、补饷、训练、边镇服从 |
| 营造军工 | 工部、建筑、军器相关人物 | 建筑、炮厂、水利、工坊 |
| 地方贯彻 | 督抚、府县、地方承宣布政使司 | 诏令落地、动乱治理、税收到省 |
| 铨选任官 | 吏部、内阁 | 补缺、调任、考成、新官上任 |
| 票拟程序 | 内阁、礼部、司礼监 | 合法性、廷议、批红、章程 |
| 厂卫监察 | 东厂、锦衣卫、都察院 | 密查、追赃、揭露账实不符 |
| 内廷传旨 | 司礼监、近侍 | 即时命令、密令、内廷工具 |

后续所有诏旨都应先看相关能力。低能力不是禁止下旨，而是必须显示代价：更慢、更贵、更容易瞒报或变形。

## UI 规划

移动端国策页顺序调整为：

1. 国策中枢。
2. 国家机器。
3. 财政账簿。
4. 疆域与军队约束。
5. 舆图、国势、省份、军队、奏疏/旨意/履约、建筑、官制。

这样玩家先看“国家为什么动不了”，再下钻“哪笔钱、哪个衙门、哪支军队”。

## 测试

- `tests/test_statecraft_center.py`
  - 顶栏库存必须来自 `state.metrics` 和 `FiscalCenter`。
  - 国库税源必须等于 `FiscalCenter.totals.province_dynamic_tax`。
  - 朝廷执行力必须来自 `organization_diagnostics()`。
  - 产能行必须包含财政、军政、营造、地方、程序等核心领域。

## 后续迁移

1. 把诏旨创建页接入 `capacity_rows`，提前显示“此旨会被哪个产能限制”。生命周期页已先接入 `statecraft_preflight`。
2. 把建筑新建/维修改成队列，消耗“营造军工”能力和国库/内库。
3. 把任命/补缺接入“铨选任官”能力，空缺不再只是组织图数字。
4. 把财政改革接入“财政署理 + 地方贯彻 + 厂卫监察”，玩家能看见清丈、查账、追赃的制度链。
5. 把军务接入“军政后勤”，欠饷、士气、边镇自专成为统一后勤面板的一部分。
