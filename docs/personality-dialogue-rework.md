# 人格与召对活人感重排

本文处理一个核心体验问题：项目里明明有性格、心盘、天罡、人脉、trait、记忆和履约账本，但玩家听起来仍像所有人在用同一套官样话。

结论：当前问题不是没有人格数据，而是 **人格没有成为输出合同**。大量资料进入了隐藏上下文、审计 payload 和执行风险判断，但最终自然语言生成只被软性提醒“要符合人物性格”。在通用官场 prompt、事实校验、工具调用、奏对目的、密令规则和履约规则共同挤压下，模型会自动滑回稳妥、含糊、万能的朝臣腔。

---

## 现状诊断

### 已有机制

项目已经具备这些人格输入：

- `content/characters.json`：人物 `style`、`personal_skills`、基础数值、小传。
- `content/npc_network.json`：人物关系、旧怨、同道、成长风险。
- `content/npc_tiangang.json`：隐藏 36 维谱尺。
- `ming_sim/context.py`：`npc_dialogue_behavior_profile()` / `npc_dialogue_behavior_brief()`。
- `ming_sim/dialogue_audit.py`：把行为档案带入奏对审计。
- `ming_sim/registry.py`：Agent system prompt 注入人物、名册、记忆、履约、密令。

这些证明“系统知道人物不同”，但不等于“玩家听见人物不同”。

### 断点

1. **人格是软提示，不是硬约束。**
   `npc_dialogue_behavior_brief()` 被塞进每轮 user 前缀，容易被 system 里的通用规则和事实块淹没。

2. **测试覆盖的是行为档案，不是最终声线。**
   现有测试能证明王承恩、毕自严、徐光启、满桂拿到不同 behavior brief；但这不保证最终回答有区别。

3. **通用 prompt 太强。**
   “谨慎含蓄、有利害权衡、不要出戏、不要乱改状态”会把所有人推向同一种安全答案。

4. **缺少可见验收标准。**
   玩家不关心隐藏标签是否正确，玩家只关心：一句话听上去是不是这个人、这个身份、这个处境。

---

## 新边界：人格必须显成玩家可感知输出

人格不再只是：

- 隐藏数值。
- 审计标签。
- 执行风险修正。
- 前端人物卡说明。

人格必须同时影响：

| 层级 | 必须显化 |
|------|----------|
| 称谓 | 臣/奴婢/臣妾/外臣等不能错 |
| 第一关注点 | 户部先谈钱粮，边将先谈兵饷，清流先谈名分，内廷先谈明旨保密 |
| 条件 | 支持不是空口支持，要提出本人会在意的条件 |
| 拒绝 | 反对要有符合身份的理由 |
| 隐瞒 | 半真半假者不能突然全知全诚 |
| 人情 | 同党、恩主、政敌、旧怨要改变说法 |
| 句式 | 老臣、边将、内侍、格物臣、后宫人物应有不同长短和转折 |

## 已落地修补

### 1. 新增人物声音合约

新增：

```python
ming_sim.context.npc_dialogue_voice_contract(name, character=...)
```

它输出 system-level 的稳定声线合同：

- 当前声线。
- 第一关注顺序。
- 说话质地。
- 常用抓手。
- 越界禁区。
- 每次回答必须显出本人差异锚点。

与每轮 `npc_dialogue_behavior_brief()` 不同，声音合约进入 Agent system instructions，优先级更高，不容易被实时事实块淹没。

### 2. Agent system 注入

`ming_sim/registry.py` 已在创建大臣/后宫 Agent 时注入声音合约。它与 `persona_self_address_rule()` 相邻，属于角色扮演硬边界。

### 3. 每轮行为档案增强

`npc_dialogue_behavior_brief()` 增加“本轮话术自检”：

```text
我是谁、我怕什么、我能办什么、我会偏袒谁。
```

并要求第一段露出差异锚点，避免所有 NPC 都给“慎重从长计议”的安全答案。

### 4. 通用大臣 prompt 加硬

`content/prompts/minister_agent.md` 明确：

- 人物声音合约不是背景资料，而是演出硬约束。
- 差异不靠机械口癖，而要落在关注点、条件、隐瞒、担责方式和句子长短上。

## 角色差异示例

同问“辽东军饷短缺，怎么办？”

### 王承恩

应先说：

- 奴婢。
- 明旨、传旨、催办。
- 内库是否可暂垫。
- 司礼监能不能盯户部回奏。

不应像阁臣一样宏论朝局。

### 毕自严

应先说：

- 国库、内库边界。
- 税源、到账率、经手衙门。
- 哪笔能拨、哪笔不能挪。
- 下月缺口。

不应只讲“臣愿为陛下分忧”。

### 徐光启

应先说：

- 实测、器械、工期、物料。
- 火器/水利/历算如何转成可验方案。
- 钱粮要分段试办。

不应只用清流名分腔。

### 满桂

应先说：

- 饷、粮、兵心、将令、期限。
- 空旨无粮不可接。
- 能战到哪一步、缺什么。

不应像户部尚书一样只盘账册。

## 后续必须补的验收

当前修补能让 prompt 更硬，但还需要更强的端到端验收：

1. **LLM 输出对比测试**
   同一问题召见 4 个不同 NPC，抽样检查回答是否有不同关注点。

2. **风格退化检测**
   若多名 NPC 回答出现高相似开头，例如都以“臣以为此事当慎重”开场，应标记退化。

3. **角色禁区测试**
   - 太监不得自称臣。
   - 后宫不得像外朝大臣一样裁断军国。
   - 边将不得开天眼谈内阁票拟细账。
   - 户部人物不得像前线亲历者一样描述战场。

4. **人格影响履约**
   半真半假、护短、旧恩、政敌、旧怨不能只影响文本，还要进入握手条件、履约难度和复命水分。

5. **前端可见提示**
   人物卡可以显示“声线锚点/本职关注/忌讳”，让玩家知道为什么这个人这样说，而不是以为 LLM 随机发癫。

---

## 架构纪律

以后新增人物机制时，必须回答：

| 问题 | 要求 |
|------|------|
| 是否影响称谓 | 是则进 `persona_self_address_rule()` 或声音合约 |
| 是否影响说话关注点 | 是则进 `npc_dialogue_voice_contract()` |
| 是否影响本轮态度 | 是则进 `npc_dialogue_behavior_profile()` |
| 是否影响承诺/握手 | 是则进 `dialogue_audit` |
| 是否影响执行结果 | 是则进 `bureaucracy` / `simulation` |
| 是否能被玩家看见 | 至少在对话、人物卡、复命或国策证据中显一个 |

性格机制如果不能改变玩家听到的话、看到的条件、后续履约或执行结果，就不算真正接入。
