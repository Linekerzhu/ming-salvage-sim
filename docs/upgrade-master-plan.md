# A. 七大设计支柱（一切系统的裁判标准）

| # | 支柱 | 一句话 | 对应系统 |
|---|------|--------|---------|
| P1 | 皇权是均衡 | 权力是百官对"别人会不会服从"的预期 | S6 势与朝堂剧场 |
| P2 | 崇祯陷阱 | 问责越狠，担责越少 | S5 任事意愿系统 |
| P3 | 注意力稀缺 | 皇帝唯一的资源是注意力 | S4 御案系统 |
| P4 | 一切数据皆证言 | 界面上每个数字都有作者 | S3 文书化黑箱 |
| P5 | 执行者即对象 | 政策要穿过被它伤害的人的手 | S2 指令生命周期 |
| P6 | 言语即落子 | 每句话都有账可记，裁决归规则 | S8 账本与信息集 |
| P7 | 悲剧值得玩 | 评价的不是输赢，而是你如何失败 | S11 史笔系统 |

**裁判用法**：后续任何新功能提案，先问它强化哪条支柱；一条都不沾的不做。

# B. 升级后的核心循环

```
                    ┌──────────────────────────────────────────┐
                    │              时间流动（日tick）             │
                    └──────────────────────────────────────────┘
                                       │
        奏疏流陆续送达御案 ◄── 官员主动奏报 / 派系出招 / 指令异常 / 密查回报
                │
        【注意力预算内处置】批红 / 留中 / 召对 / 发部议
                │                                    ▲
        旨意进入生命周期：送达→执行(旬检定)→结算       │
                │                                    │
        经手链条上的利益受损者拖延/打折/封驳 ──► 异常节点（时间暂停）
                │                                    │
        玩家干预：催办/换人/买单/问罪 ──► 更新：势、risk_aversion、账本
                │                                    │
        账实分离落库（reported/actual）──► 审计/密查玩法 ──► 揭穿或被骗
                │
        硬阈值扫描 ──► 危机事件（哗变/民变/赤字三选一）
                │
        朔日大朝：月报（史官汇总）+ 中兴指数 + 史评预览
                │
        ……终局：史笔立传 + 结局光谱
```

恶性循环（玩家要学会驯服的）：
**严惩失败 → risk_aversion↑ → 请旨奏疏暴增+无人任事 → 御案过载 → 误批/积压 → 更多失败**

良性循环（玩家要学会建立的）：
**为失败的忠臣买单 → risk_aversion↓ → 官员主动任事 → 御案减负 → 注意力投向战略**

# C. 系统设计

## S1 时间引擎（半即时地基）

- 最小单位**日**；1x/3x/暂停 + "跳到下一节点"。`turn = current_day // 30 + 1` 兼容旧逻辑。
- **分层结算**：
  - 规则层（每日，零 LLM）：财政日摊（flows.py 公式 ÷30）、欠饷累积、issue 惯性、
    指令进度、情报倒计时、硬阈值扫描（S10）。
  - LLM 层（仅节点）：指令结算、事件叙事、旬报/月报、派系出招、票拟生成。
- **调度表**（系统心脏）：
  ```sql
  CREATE TABLE scheduled_resolutions (
      id INTEGER PRIMARY KEY,
      kind TEXT,        -- directive_step|event_check|report|agreement_due
                        -- |intel_arrival|faction_move|memorial_arrival|seed_check
      due_day INTEGER, payload TEXT,
      status TEXT,      -- pending|fired|cancelled
      requires_llm INTEGER, auto_pause INTEGER
  );
  ```
- **自动暂停分级**：红（哗变/城破/重臣亡/危机抉择）必停；黄（指令异常、密查回报、
  约定到期）默认停可关；蓝（一般奏疏到案）仅角标。进入召对界面时间静止。
- **LLM 异步队列**：节点入队后该事项游戏内冻结（"在途"），世界继续流动；
  完成后以"奏报送达"形式呈现——LLM 延迟被驿传时间合理化。并发上限 2~3。
- **朔日大朝**：月报（simulator 降级为史官，只汇总已结算事实，不再推演——
  幻觉风险大降）、财政月账、中兴指数刷新、史评预览。

## S2 指令生命周期与经手链条（P5 的机制化）

状态机：`draft → issued → in_transit(lead_days) → executing → done/aborted`，
executing 期间每旬一次**执行检定**。

**经手链条**：颁诏时规则层生成执行链（主办官员 → 经手官署 → 地方官），
逐环计算 `利益受损度`（政策类别 × 该官员派系立场 × 个人利益标签）。颁诏界面
向玩家展示链条与风险——这是"看得见的官僚迟滞"。

**执行检定（旬）**：
```
roll = 官署执行力(bureaucracy.organization_diagnostics 已有)
     + 主办官员 ability 修正
     + (势 - 50) × 0.3                 ← S6
     - 链条最大利益受损度 × 0.4          ← P5
     - risk_aversion 修正(任务含风险时)  ← S5
     + 账本修正(承诺兑现史/旧怨)         ← S8
结果分档：顺利 / 拖延(进度停) / 打折(actual↓ 但 reported 照报) / 封驳 / 异常事件
```
打折档直接写入账实分离两列（S3）：`integrity_actual < integrity_reported`，
玩家此刻看到的是粉饰版。

**中途干预**（异常节点暂停时）：催办（加速，unrest+/怨气+）、换人主办、加拨钱粮、
派员督办（占用官员）、收回成命（势-）。每项是带小工期的子指令。

**工期公式**：`基础工期(类别表) × 执行力修正 × 距离修正(京畿1.0~边地1.8) × 阻力修正`。

## S3 文书化黑箱：一切数据皆证言（P4 的机制化）

- **账实分离落库**：关键数值（兵额、饷银、仓储、灾情、指令执行率）一律两列：
  `reported`（某衙门呈报，玩家可见）与 `actual`（隐藏真值）。差值即空饷/瞒报/贪墨的量化。
  ```sql
  CREATE TABLE report_ledger (
      id INTEGER PRIMARY KEY,
      entity_kind TEXT, entity_id TEXT, field TEXT,
      reported_value REAL, actual_value REAL,
      author_org TEXT, author_character TEXT, reported_day INTEGER
  );
  ```
- **UI 文书化**：废除"国家面板"。玩家看到的是各衙门呈报文书，每个数字挂
  作者、衙门、日期。`/api/characters` 不再输出 loyalty/integrity 真值，
  改输出文书评语 + 出处（"吏部考语：清慎勤 / 东厂访单：颇通馈遗"）。
- **审计即侦探**：交叉矛盾（兵部报的兵额 × 户部发的饷 ≠ 实情）由前端
  并排呈现原始文书，发现矛盾是玩家的乐趣，不替玩家自动标红（高难度）
  或可选标红（低难度）。
- **盘库/校阅/巡按**：审计类指令走 S2 生命周期，成功则该实体若干字段
  reported→actual 校正并曝光责任人；失败或遇反侦则可能拿到二次伪造的数字。
- 钱粮兵额的 reported 值皇帝当然可见（不搞战争迷雾式遮蔽）——黑箱的本体是
  reported 与 actual 的裂缝，以及人心（S8 信息集）。

## S4 御案系统：注意力经济（P3 的机制化）

- **注意力点数**：每日 N 点（基准 12，受健康/后宫/经筵日程修正）。消耗：
  细读奏疏全文 2 / 依票拟批红 0.5 / 亲笔批答 1 / 召对 4（且暂停时间）/
  发部议 0.5 / 留中 0。
- **奏疏表**：
  ```sql
  CREATE TABLE memorials (
      id INTEGER PRIMARY KEY,
      author_id TEXT, org TEXT, kind TEXT,  -- 请款|荐人|弹章|告变|请罪|请旨|密揭
      urgency TEXT, summary TEXT, full_text TEXT,
      piaoni TEXT,           -- 内阁票拟（LLM 以当值阁臣立场生成）
      arrived_day INTEGER, status TEXT,  -- pending|approved|denied|shelved|referred
      shelved_days INTEGER   -- 留中计数：积压有后果（上疏人怨气+、派系解读风向）
  );
  ```
- **过滤器是有立场的人**：票拟由当值阁臣 agent 生成（带派系滤镜）；司礼监可
  配置"代批"低优先级奏疏（省注意力，但代批方向取决于掌印是谁的人）。
  谁替你筛选信息，谁就在塑造你眼中的世界——这是人事任免的新维度。
- **勤政陷阱**：连续高强度亲批 → 注意力上限临时下降 + 误批概率（亲批检定
  小概率出"朝令夕改"事件，势-）。机制上温和地教玩家放权。
- 奏疏流量公式见 S5——它是崇祯陷阱的传导介质。

## S5 任事意愿系统：崇祯陷阱（P2 的机制化，本作核心循环）

- **全局变量 `risk_aversion`（RA，0-100，初始 40）**——官僚集体的"任事风险"判断：
  - 上升事件：处死/重惩办事失败的官员（+8~15，公开处刑取上限）、追责扩大化（+5）、
    临阵换帅（+5）、承诺的支持没给却问罪（+10）。
  - 下降事件：**为失败的忠臣买单**（公开担责/抚恤/复用，-5~10）、败后只罚首恶
    不搞株连（-3）、皇帝公开认错下罪己诏（-8，但势-5：真实取舍）。
  - 自然回归：每月向 40 缓慢回归 ±1。
- **RA 的全局效果**：
  - 请旨奏疏量 `× (1 + RA/100)`（御案被淹）
  - 官员主动提案/主动奏报概率 `× (1 - RA/150)`
  - 执行检定中"推诿/求免责"异常概率 `+ RA × 0.3%`
  - 召对中官员敢说真话的倾向（接入 negotiation 心理量表的修正项）
- **可视化**：御案积压量与"百官任事意愿"（即 100-RA）双趋势线并排，
  让玩家亲眼看见循环；史评预览（S11）会点破："上多疑而好杀，臣下莫敢任事。"
- 与惩罚的张力设计：惩罚同时是 S6 势的来源（立威）——**短期立威 vs 长期寒心**
  是本作最重要的单一取舍，两个变量必须同屏展示。

## S6 势与朝堂剧场（P1 的机制化）

- **全局变量 `势`（0-100，初始 55**，新君登基自带恩威）：百官对"抗命会被惩罚、
  服从是大流"的信念聚合。
  - 上升：公开惩处抗命且坐实（+3~8）、政令如期落地（+1/道）、大案办成（+5~10）。
  - 下降：抗命/封驳未被回应（-5~10）、朝令夕改（-4）、重大弹章留中不发（-2）、
    指令大面积烂尾（-3/道）。
- **效果**：执行检定全局修正 `(势-50)×0.3`；势 < 35 时派系出招频率上调、
  official 试探性小抗命事件解锁；势 > 70 时解锁"乾纲独断"类指令
  （绕过部议直接执行，但每用一次 RA+3——独断与寒心连动）。
- **公开/私下二象性**：每个处置动作标 public/private。公开动作结算时更新
  全体观众信念（势、RA、各派 heat），私下动作只影响当事人但有泄露概率
  （泄露后按公开结算且加"刻薄"修饰）。廷杖、罪己诏、午门献俘等仪式动作
  是纯信号类指令——不改钱粮，只改信念。

## S7 派系主动 AI 与官员主动性

- 派系字段升级：`agenda`（阶段诉求）、`heat`（敌意度，政策损其利则累积）、
  现有 leverage/satisfaction 保留。
- **每旬 faction_move 节点**：规则层按 heat 概率与配额（全局每旬 ≤3 招）决定
  谁出招，LLM 谋士 agent 生成具体内容：弹章（入奏疏流）、联名请愿、廷议发难、
  荐人（人事提案入奏疏流）、暗手（散流言→污染 report_ledger 若干条目、
  地方掣肘→给指令叠加阻力）。
- **官员主动奏报**：概率受 RA（S5）与个人 courage/立场驱动。内容由该官员
  agent 在自己的信息集（S8）内生成——他只会奏报他知道的，且带他的立场滤镜。
- 出招与奏报全部以文书形式进御案（S4），不弹系统框——世界出招和玩家视野
  统一在"一摞奏疏"里（P4 一致性）。

## S8 言语账本与信息集隔离（P6 的机制化）

- **账本强化**（基于现有 agreement_ledger/dialogue_goals）：
  - 双向化：官员对皇帝也有 `trust` 值。皇帝失诺 → 该官员 trust↓ → 握手
    threshold 抬高、执行打折概率升、且其派系内传播（同派官员 trust 小幅连坐）。
  - 抓手化：官员失诺自动生成"可问罪抓手"条目，玩家可在召对出示（握手评分修正）
    或交科道发起弹劾（转指令）。
  - 当众羞辱/廷杖/破格恩赏全部入账，作为执行检定与心理量表的长期修正项。
- **信息集隔离（架构铁律）**：每个 NPC agent 的上下文只包含其身份应知信息：
  自己衙门的 reported 数据、自己派系的内部消息、与自己相关的账本条目、
  公开邸报。不喂全局真值。欺骗、误传、信息差由此自然涌现，无需编写说谎逻辑。
  - 实现：`context.py` 增加 `build_info_scope(character_id)`，按
    衙门/派系/地域/账本关联过滤；所有大臣 agent 的 prompt 组装改走此函数。
  - 这是 LLM harness 相对脚本游戏的代差优势，列为不可妥协项。

## S9 密查体系（黑箱的主动玩法）

- 两条线，均走 S2 指令生命周期（有工期、会失败、会被反侦）：
  - **厂卫线**（东厂/锦衣卫）：快（旬级）、准（直接校正 report_ledger 若干条 +
    给出官员真实立场区间），但每次累积"厂卫横行" issue bar（言官弹劾、民怨），
    且厂督本人也是信息集隔离的 agent——查人的人同样要被查。
  - **科道线**（巡按/科道官）：慢（月级）、带派系滤镜（报告偏向巡按的派系），
    无政治成本。
- 产出**情报报告**（入奏疏流，密揭类）：带 credibility；被反侦时可能拿到
  喂过来的假情报（写入 report_ledger 一条新的伪 reported 记录——
  谎言污染的是文书层，与 S3 完全同构）。

## S10 硬阈值与因果伏笔（数值可信度）

- **threshold_rules.json**（数据驱动）：是否发生由规则定，如何发生由 LLM 写。

  | 条件（日扫描） | 必然后果 | LLM 职责 |
  |---|---|---|
  | army.arrears > 3 月饷 且 morale<40 | 哗变立项 | 写过程/首领/诉求 |
  | region.unrest>70 且 grain<1 月 | 民变立项 | 写火星与首领 |
  | 国库<0 连续 3 月 | 强制危机抉择：捐俸/加派/搜刮内库 三选一 | 写朝议反应 |
  | 官员 grievance>80 | 怠工/请辞/倒向反对派 | 写其表现 |
  | issue 触底 | effect_on_fail 必落库 | 写失败叙事 |

- 提取 schema 中被硬规则覆盖的字段改**只读**——LLM 无权写这些 delta。
- **因果伏笔表 causal_seeds**：重大决策落库时埋种子
  `(trigger_condition, fuse_days, payload)`，规则层定期检查萌发——
  "裁驿站 → 两年后流寇名册里出现驿卒"。延迟代价由此可编排、可追溯。
- 前端**预警仪表**：每条阈值规则给进度条（"宣大军欠饷 2.4/3.0 月"）。
  注意：仪表显示的是 reported 值（S3）——账被做假时仪表也会骗你，
  这是有意为之的设计统一。

## S11 史笔系统与结局光谱（P7 的机制化）

- **素材**：S8 账本 + 关键决策记录（chapter memories 已有）天然就是史料。
- **史评预览**（过程中）：起居注片段、经筵日讲官委婉评点，每季度一条，
  让玩家中途感知"史书会怎么写我"；RA 高企时出现"上多疑，臣下莫敢任事"
  之类的判词——史笔同时是 S5 的软反馈渠道。
- **终局立传**：LLM 以清修《明史·本纪》体例为玩家作传，笔调由实际作为决定
  （"刚愎而勤，亡于自用" vs "知人善任，惜乎时不我与"）。
- **结局光谱**（替代二值结局）：撑到 1647 或中途崩盘时，按中兴指数 + 关键
  issue 状态 + 史笔基调归档：回天乏术 / 划江而治 / 中兴在望 / 乾纲独断的代价 /
  煤山（但传记可以是同情的——失败方式比失败本身重要）。
- 成本：终局一次 advanced 调用 + 季度预览每次 ≤300 token。**性价比全案最高，提前实装。**

## S12 中兴指数与阶段诏题（节奏层）

- 中兴指数（0-100，月刷）：财政健康/九边稳定/流寇压制/吏治/民心 五分项加权，
  朔日大朝展示折线。是趋势仪表不是胜利条件。
- 阶段诏题：1628-29 站稳脚跟 / 1629-31 己巳之变 / 1631-36 双线作战 / …
  每阶段 2~3 个可量化目标（"己巳之变前蓟镇 supply≥60"），完成给势与叙事奖励。
  兼作软教程，替代未实现的开局教程。

# D. LLM Harness 架构调整

## 角色重划分

| 角色 | 模型档 | 上下文 | 输出 | 变化 |
|------|--------|--------|------|------|
| 大臣 agent | 主 | **信息集隔离**（S8） | 对话流 | 上下文按身份过滤（新） |
| 阁臣票拟 | 主 | 单份奏疏 + 阁臣立场 | ≤200字票拟 | 新增 |
| 书办（审计/提取） | advanced | **局部盘面**（单指令/单事件相关实体） | 结构化 JSON | 从全局瘦身为局部（关键改造） |
| 史官（旬/月报） | 主 | 已结算事实清单 | 邸报叙事 | 从"推演者"降级为"汇总者"（防幻觉） |
| 派系谋士 | 主 | 该派 agenda+heat+近事 | ≤500字出招 | 新增，每旬配额制 |
| 史笔 | advanced | 决策账本+章节记忆 | 立传/季评 | 新增 |
| 审计三官（对话） | advanced | 现状保留 | 现状保留 | 不变 |

## 成本模型

- 月末巨型推演（全局盘面 × 1 次）→ 多次小结算（局部盘面 × N 次）。
  单次输入预计降为原来的 1/5~1/10，次数升为 8~15 次/月，总量预计持平略降。
- 闸门：异步队列并发 ≤3；派系出招每旬 ≤3；票拟仅对 urgency≥中 的奏疏生成
  （低级奏疏用模板票拟）；token_stats.py 按新 caller_tag 分桶，M2 上线后
  与基线对比，超 120% 则收紧配额。

# F. 实施路线图

> 原则：每个里程碑结束时游戏**必须可玩**；每个里程碑都有不可让步的验收标准。
> 排序按"工程依赖 × 设计价值"折中：史笔提前，黑箱建表提前埋。

## M0 准备（小）
- threshold_rules.json / directive_categories.json 内容整理（纯数据工作）。
- token 用量基线测量（现有 token_stats 跑 3 个月存档）。
- report_ledger / memorials 表 schema 评审——**虽然 M3/M4 才用，建表语句
  现在定稿**，避免后续迁移。

## M1 时间地基 + 硬阈值 + 史笔 v0（中）
- S1 步骤：current_day/调度表/日 tick/财政日摊/时钟与速度 UI（WebSocket 推送）。
  月末 LLM 结算管线暂时原样保留（挂在朔日节点上）。
- S10：阈值日扫描 + 前端预警仪表；提取 schema 只读化。
- S11 v0：终局史笔立传（素材用现有 chapter memories）。
- **验收**：旧存档可迁移续玩；时间可暂停/调速；欠饷哗变 100% 按规则触发且
  LLM 只写叙事；打完一局能收到一篇明史体传记。
- 涉及：db.py, models.py, flows.py, session.py, web_app.py, issues.py, simulation.py, web/src

## M2 指令生命周期（大，半即时核心）
- S2 全部：状态机、经手链条、工期公式、旬检定、异常节点与五种干预。
- S1 收尾：月末大结算拆散为按指令分片入调度表；LLM 异步队列
  （新建 ming_sim/scheduler.py）；史官模式月报。
- S3 埋点：directives 的 integrity_actual/reported 双列开始分叉记录
  （UI 暂只显示 reported，不解释——为 M4 留悬念）。
- **验收**：一道旨意从颁到结全程可视、中途可催办换人；同时 3 道指令并行
  执行互不阻塞；token 总量 ≤ 基线 120%。
- 涉及：decree.py, simulation.py, bureaucracy.py, db.py, 新 scheduler.py, web/src

## M3 御案与崇祯陷阱（大，本作灵魂）
- S4：memorials 表、奏疏流送达、注意力点数、批红五动作、票拟生成、
  留中计数与后果、司礼监代批配置。
- S5：risk_aversion 全量（事件表、流量挂钩、提案率挂钩、买单动作）、
  双趋势线 UI。
- S7 部分：官员主动奏报（派系出招留到 M5）。
- S11 v1：季度史评预览（接 RA 判词）。
- **验收**：不处理奏疏会产生可感知的后果；连续严惩后能观测到请旨量上升、
  主动奏报下降；"为忠臣买单"动作可用且趋势线可见回落。
- 涉及：web_app.py, db.py, dialogue_goals.py, negotiation.py, web/src

## M4 文书化黑箱与密查（大）
- S3 全量：report_ledger 投入使用、characters API 真值下线改文书评语、
  UI 文书化改造（数字挂作者）、矛盾并排呈现。
- S9：厂卫/科道两线密查指令、情报报告、反侦与假情报。
- S8 信息集隔离：context.py 的 build_info_scope + 全部大臣 agent 接入。
- **验收**：玩家无法从任何 API 拿到官员属性真值与 actual 列；一次完整的
  "发现账实矛盾→派员盘库→揭穿瞒报→问责"链路可玩通；两个大臣对同一事件
  的说法可以不同且各自符合其信息集。
- 涉及：web_app.py, context.py, db.py, agents.py, web/src（最大头在前端）

## M5 朝堂剧场（中）
- S6：势变量、公开/私下二象性、信号类指令（廷杖/罪己诏/献俘）、
  乾纲独断解锁、势-RA 同屏取舍展示。
- S7 收尾：派系 agenda/heat、每旬出招全量。
- S8 收尾：双向 trust、问罪抓手。
- **验收**：派系会主动给玩家制造麻烦；公开处置一个抗命者后可观测到

- 涉及：db.py, political_reactions.py, dialogue_audit.py, negotiation.py, web/src

## M6 节奏与收束（小）

- **验收**：新玩家不读文档能靠阶段诏题上手前三个月；一局打完结局与

# G. 风险与对策

| 风险 | 对策 |
|------|------|
| token 成本失控 | 局部上下文 + 配额闸门 + M2 起每里程碑对比基线，超 120% 收紧 |
| 节点轰炸、节奏失控 | 暂停分级（红必停/黄可关/蓝角标）+ 每旬节点配额 + "跳到下一红点" |
| LLM 与规则层打架 | 硬规则字段在提取 schema 中只读；史官只汇总不推演 |
| 黑箱劝退新手 | 难度分层：低难度自动标红文书矛盾、显示置信评语；高难度全裸文书 |
| RA/势 沦为又两条数值条 | 两者不直接显示数字，只以判词+趋势线+史评呈现（保持"信念"的质感） |
| 范围蔓延 | 支柱裁判法（A 节）：不沾支柱的提案不做；每里程碑必须可玩 |
| 存档断代 | M1 做一次性迁移器；M2 起 schema 变更全部走增量 ALTER + 默认值 |
