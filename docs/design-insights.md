# 设计洞察：这款政治游戏到底在模拟什么

> 状态：设计哲学稿 v1（2026-06）
> 与 design-upgrade-semi-realtime.md 配套：那份回答"怎么改机制"，
> 这份回答"机制为什么而存在"。每条洞察附机制含义，供后续系统设计对照。

---

## 1. 皇权不是一个数值，而是一种均衡

权力是所有人对"别人会不会服从你"的预期。崇祯三个月扳倒魏忠贤，
靠的是百官同时判断"其他人都会抛弃魏"——均衡瞬间翻转，而非任何属性值的比拼。

**机制含义**：
- "势"不是皇帝的属性，而是百官信念的聚合变量：靠被看见的服从累积，
  因被看见的抗命未受罚而崩塌。
- 同一道旨意，势高时是命令（执行检定加成），势低时是建议（官员观望）。
- 朝堂即剧场：每个公开行为（廷杖、褒奖、留中）的真正受众是全体官员，
  结算时应更新的是所有观众的信念，而不只是当事人的属性。
- 势可以被"试探"：派系出招中应有专门试探皇帝底线的招式（小抗命），
  皇帝的回应方式直接决定势的走向。

## 2. 崇祯陷阱：问责越狠，担责越少（核心循环候选）

史实：崇祯十七年五十相、杀七总督，终局是无人任事、事事请旨、
万事归咎于上。这是本游戏独有的题眼。

**机制含义**——把它做成游戏最核心的恶性循环：
1. 惩罚办砸事的官员 → 全体官员更新"任事风险"先验（全局变量 risk_aversion）
2. risk_aversion 高 → 推诿率↑、奏疏请旨率↑、官员主动提案率↓
3. 待决事项涌向御案 → 玩家注意力（见 §3）过载
4. 过载 → 误批、积压 → 更多失败 → 回到 1
- 破局手段必须存在且违反直觉：为失败的忠臣买单（公开担责、抚恤、复用），
  短期掉势/掉威望，长期降 risk_aversion。
- UI 应让玩家"看见"这个循环：御案积压量与官员任事意愿的趋势线并排展示。

## 3. 皇帝唯一稀缺的资源是注意力

票拟、批红存在的原因就是皇帝读不完天下。多数游戏给玩家上帝视角 +
无限行动，本游戏应反着来。

**机制含义**：
- 奏疏流量设计为略超玩家处理能力（半即时时间引擎是前提）。
- 内阁/司礼监作为可配置的"注意力过滤器"：票拟质量、扣压倾向、
  派系滤镜都取决于你放了谁在那个位置。谁替你筛选信息，谁就在塑造世界。
- "勤政"是陷阱选项：事必躬亲导致积压惩罚与势的损耗（朝令夕改）；
  "放权给谁"才是战略决策。
- 与崇祯陷阱（§2）联动：risk_aversion 越高，请旨奏疏越多，注意力越不够用。

## 4. 不存在客观界面：你看到的国家就是一摞奏疏

政治迷雾是文本性的。比"真值加噪声"更深一层：界面上每个数字都有作者。

**机制含义**：
- UI 彻底文书化（diegetic）：没有"国家面板"，只有各衙门呈报。
  国库余额是户部报的，兵额是兵部报的，每个数字挂作者与日期。
- 账实分离落库：每个关键数值存 reported（某衙门报的）与 actual（隐藏真值）
  两列；差值即贪腐/空饷/瞒报的量化。
- 审计即侦探玩法：交叉核对两份呈报的矛盾（兵部兵额 × 户部饷银 ≠ 实发）
  是玩家主动玩法；派员盘库/校阅是带工期带风险的指令。
- 这是"黑箱"设计初衷的完全体：黑箱不是加迷雾，而是"一切数据皆证言"。

## 5. 改革的执行者就是改革的对象

明末死结：向士绅收税，而官僚就是士绅。任何政策都要穿过被它伤害的人的手。

**机制含义**：
- 政策结算时显式计算"经手链条"：每道指令列出执行链上各环节官员的
  利益受损度，受损度直接转化为打折/拖延概率与派系 heat。
- 不设最优解按钮。检验标准：能用纯效率比较出优劣的决策，不是政治决策。
  每个重大选项都应在玩家在乎的不同价值之间取舍，且部分代价延迟显形
  （裁驿站 → 两年后流寇骨干里出现驿卒）。
- 延迟代价用"因果伏笔"表实现：决策落库时埋 seed（条件 + 引信期），
  规则层定期检查萌发。

## 6. 言语即落子（LLM harness 的立身原则）

LLM 游戏最大风险是叙事泥潭——什么都能聊，什么都不算数。
对策不是限制对话，而是让每句话都有账可记。

**机制含义**：
- 承诺、威胁、当众羞辱、许愿全部进账本（现有 agreement_ledger 方向正确），
  全部生利息：失信抬高后续握手阈值，旧怨修正执行检定。
- LLM 职责严格限定为"书办 + 史官"：把言语翻译成账目（审计），
  把结果解释成叙事（邸报）。裁决权归规则层。
- 信息集隔离：每个 NPC agent 只喂它按身份应知的信息集。
  欺骗、误传、信息差由此自然涌现，无需编写"说谎逻辑"——
  这是 LLM harness 相对传统脚本游戏的真正代差优势，应作为架构铁律。

## 7. 这是悲剧：让失败值得玩

1628 年的大明大概率要亡，这是题材本身而非缺陷。终局评价不该是赢/输，
而是"你以什么方式、为了什么而失败"。

**机制含义**：
- 史笔系统：终局由"后世史官"（LLM 以清修《明史》本纪的口吻）为玩家立传，
  输入是全程关键决策账本（§6 的账本天然就是素材），输出笔调随作为而变：
  "刚愎而勤，亡于自用" vs "知人善任，惜乎时不我与"。
- 立传依据应可被玩家中途窥见：经筵日讲官的委婉评价、起居注的只言片语，
  作为过程中的"史评预览"。
- 设计初衷"延缓、改变或重新解释大明的走向"——前两个词大家都做，
  第三个词（重新解释）才是本作灵魂，史笔系统是它的机制化身。

## 对实施优先级的修正

semi-realtime 方案的 P1–P6 按工程依赖排序；按设计价值重排：

1. **崇祯陷阱（§2）升为一等公民**——它给游戏一个独一无二的核心循环，
   实现上只需一个全局 risk_aversion 变量 + 奏疏流量挂钩 + 担责/买单动作，
   可并入 P4（世界出招）一起做。
2. **文书化界面（§4）取代"印象值"成为黑箱主方案**——reported/actual
   双列落库应在 P2（指令生命周期）建表时一并埋好，避免日后迁移。
3. 势（§1）可后置：先用现有 leverage/satisfaction 凑合，
   等 §2、§4 跑通后再引入信念聚合模型。
4. 史笔系统（§7）成本极低（一次终局 LLM 调用 + 账本素材），
   建议提前到任何一个可玩里程碑就加上——它能立刻改变测试者对失败的体验。
